# 슬래시(`/`) 명령어 요약

`/`로 시작해 텔레그램/터미널/웹에서 **AI를 거치지 않고 즉시 실행**되는 명령어 전체
목록입니다. (`/` 없이 입력하면 자연어로 간주되어 Claude가 명령어로 변환한 뒤 확인을
거칩니다 — 그 변환 규칙은 이 문서가 아니라 `docs/command_guide_for_ai.md`가 담당합니다.)

- 세 클라이언트(`src/run/main.py`/`src/run/terminal.py`/`src/web/client.py`) 모두 같은
  `src/commands/*_command.py` 핸들러를 공유하므로 동작은 동일합니다. 여기 예시는 `/`
  접두어 기준(텔레그램/웹)으로 적었습니다 — 터미널에서도 `/` 그대로 입력하면 됩니다.
- 국내 종목은 6자리 코드(`005930`), 해외(미국) 종목은 티커(`IONQ`)를 사용합니다.
  `buy`/`sell`/`srch`는 종목명으로 입력해도 로컬 종목마스터가 코드로 변환해 줍니다
  (예: `/buy 삼성전자 10`).
- 새 명령어를 추가/변경할 때는 이 문서도 함께 갱신하세요(`CLAUDE.md` 필수 규칙 5번은
  `docs/command_guide_for_ai.md`를 가리키지만, 이 문서도 실제 명령어 목록과 어긋나지 않게
  유지해야 합니다).

## 1. 인증 및 상태

### `/login`
KB증권 OAuth2 접근토큰을 발급받아 거래를 시작합니다.

| 사용법 | 설명 |
|---|---|
| `/login real` | 운영환경(실거래)으로 로그인 |

KB증권 개발환경(모의투자)은 아직 제공되지 않아 `dev`는 정상 동작하지 않습니다. 웹
클라이언트는 `/login`을 직접 입력하는 대신 설정 화면(`/settings.html`)에서 앱키를
저장하면 자동으로 로그인됩니다.

**동작 방식**: `src/commands/login_command.py`의 `handle_login()` → `src/api/auth.py`의
`get_token()`이 KB증권 OAuth2 토큰 발급 API(`POST /oauth2/token`, `docs/api/md/OAuth/토큰
발급-*.md`) 1건만 호출한다. `config.py`의 `real_client_key`/`real_client_secret`(또는
`dev_*`)와 `config.device_info`(기기 정보, 단말식별용)를 요청 바디에 실어 보내고,
응답의 `access_token`/`expires_in`을 그대로 `SessionManager.set_token()`
(`src/utils/session.py`)에 저장한다 — **파일에 저장되지 않고 프로세스 메모리에만
존재**하므로 재시작하면 다시 로그인해야 한다. 웹 클라이언트는 브라우저 세션(쿠키)당
`WebClient` 인스턴스가 하나씩 있고 그 인스턴스의 `SessionManager`도 별도이므로 토큰이
사용자별로 분리된다(`src/web/session_store.py`).

**실행 검증 (2026-07-20)**: ✅ `/login real` → 실제 KB증권 OAuth2 토큰 발급 API를
호출해 정상적으로 접근 토큰을 발급받고 만료 시각까지 정확히 표시됨을 확인.

**예시**
```
/login real
```

### `/status`
현재 로그인 여부, 거래 환경, 토큰 남은 시간을 확인합니다.

```
/status
```

**동작 방식**: `handle_status()`는 API를 호출하지 않고 `SessionManager`(메모리)에 저장된
`access_token`/`trading_env`/`token_expires_at`만 읽어 현재 시각과 비교해 남은 유효시간을
계산해 보여준다.

**실행 검증 (2026-07-20)**: ✅ 로그인 전 "로그인되지 않음" 안내, 로그인 후 환경/남은
유효시간이 정확히 표시됨을 확인.

## 2. 조회

### `/srch`
종목의 현재가·등락률·거래량·PER/PBR 등 기본 정보를 조회합니다. **국내 + 미국 주식 모두 지원.**

```
/srch {종목코드}
```

**예시**
```
/srch 005930        (삼성전자)
/srch IONQ           (미국 아이온큐)
```

**동작 방식**: `src/commands/srch_command.py`. 종목코드가 6자리 숫자면 국내로 보고
`src/api/price_info.py`의 `ivu10140`(국내 주식 기본시세) 1건만 호출한다. 6자리 숫자가
아니면 `mst/api/openapi_field_foren-us.mst`(로컬 종목마스터)에서 해당 티커를 찾아보고
(API 호출 없음), 등록된 해외 종목이면 `gss10030`(해외 주식 기본시세) 1건을 호출한다 —
둘 다 아니면 API를 호출하지 않고 바로 오류를 반환한다. API는 1건만 쓰지만 "국내/해외
어느 쪽으로 부를지"를 로컬 데이터로 먼저 결정하는 조합이다.

**실행 검증 (2026-07-20)**: ✅ `/srch 005930` → 실제 KB API 응답으로 삼성전자 시세를
정상 출력.

### `/rank`
상위 종목 랭킹을 조회합니다.

| 사용법 | 설명 |
|---|---|
| `/rank` | 메뉴 표시 |
| `/rank 1` | 거래대금상위 Top 20 |
| `/rank 2` | 등락률상위 Top 20 |
| `/rank 3` | 거래량상위 Top 20 |
| `/rank 4` | 업종랭킹 |

**예시**
```
/rank 2
```

**동작 방식**: `src/commands/rank_command.py`의 `RANK_FUNCS` 딕셔너리가 번호→API를
매핑한다 — 1:`ivu10210`(거래대금상위), 2:`ivu10240`(등락률상위), 3:`ivu10280`(거래량상위),
4:`ivm30010`(업종랭킹, `src/api/rank_info.py`). 매 호출 KB API 1건만 실행하며 조합 없음.

**실행 검증 (2026-07-20)**: ✅ `/rank`(메뉴), `/rank 3`(거래량상위) 정상 응답 확인
(호출 시점에 거래량상위 데이터가 "해당자료가 없습니다"로 빈 목록이었으나, 이는 장운영
시간 등 KB 서버 측 데이터 상태 문제이며 API 호출/응답 처리 로직 자체는 정상 동작).

### `/report`, `/r`
보유종목 현황과 미체결 주문을 조회합니다(둘은 완전히 동일한 명령의 별칭).

```
/report
/r
```

**동작 방식**: `src/commands/report_command.py`가 KB API 2건을 순서대로 호출한다 —
① `ssqm1801`(보유주식 조회)로 보유 종목 목록, ② `ssqm2341`(체결/미체결 조회, 당일
날짜 `ordr_dt`+`ccls_clsf="2"`로 미체결만)로 미체결 주문 목록. 두 API는 서로 독립적이라
①이 실패해도 즉시 반환하지만, ②가 실패하면 "조회 실패" 문구만 이어붙이고 ①의 결과는
그대로 보여준다(부분 실패 허용).

**실행 검증 (2026-07-20)**: ✅ 보유 종목/미체결 주문 모두 정상 조회(현재 보유·미체결
없음 응답).

### `/mst`
종목마스터(로컬 파일) 로드 현황을 조회합니다. API 호출 없이 `mst/api/*.mst`만 읽습니다.

```
/mst
```

**동작 방식**: `src/commands/mst_command.py` → `src/utils/stock_master.py`의
`load_all()`이 `mst/api/openapi_field_kospi-kosdaq.mst`(국내, 코스피+코스닥 통합)와
`mst/api/openapi_field_foren-us.mst`(해외)를 파싱해 종목 수만 센다. KB API 호출이
전혀 없다.

**실행 검증 (2026-07-20)**: ✅ 코스피/코스닥/해외 종목 수 정상 표시.

### `/stcd`
종목명/종목코드 키워드로 검색합니다. 국내는 종목코드 일부로도 검색됩니다.

| 사용법 | 설명 |
|---|---|
| `/stcd {키워드}` | 키워드 검색 |
| `/stcd {키워드1} {키워드2} ...` | 여러 키워드 OR 검색 |

**예시**
```
/stcd 삼성
/stcd 005930
/stcd 카카오 네이버
```

**동작 방식**: `src/commands/stcd_command.py` → `stock_master.search_domestic()`/
`search_overseas()`가 `/mst`와 동일한 로컬 mst 데이터에서 이름/코드 부분일치로
검색한다(API 호출 없음). 여러 키워드는 OR로 합친 뒤 코드/티커 기준 중복 제거.

**실행 검증 (2026-07-20)**: ✅ `/stcd 삼성` → 국내 10건 정상 검색됨.

### `/investor`
종목의 투자자별(개인/외국인/기관) 누적 순매수 차트를 이미지로 생성합니다. **국내 전용**
(해외는 KB API에 대응 API가 없음). 텔레그램은 사진으로 전송, 웹/터미널은 이미지 파일
경로를 반환합니다.

```
/investor {종목코드} {개월수}
```

**예시**
```
/investor 005930 3   (삼성전자 최근 3개월)
```

**동작 방식**: `src/commands/investor_command.py`가 `ivu10430`(투자자별 매매동향,
`src/api/investor_chart.py`) 1건을 `acml_clsf="1"`(누적구분)로 호출한다 — KB가 이미
누적 순매수를 계산해 내려주므로 일별 데이터를 받아 직접 누적합(cumsum)할 필요가
없다. 응답으로 받은 개인/외국인/기관계 시계열을 matplotlib으로 선 그래프 PNG로
그려 임시 파일(`tempfile`)로 저장한다. 텔레그램은 그 PNG를 `send_photo`로 전송 후
파일을 삭제하고, 웹/터미널은 파일 경로 문자열만 반환한다(파일이 그대로 남음).

**실행 검증 (2026-07-20)**: ✅ `/investor 005930 1` → 실제 API 응답으로 21일치
데이터를 받아 PNG 차트 파일이 정상 생성됨을 확인.

## 3. 매매

### `/buy`
종목을 매수합니다. **국내(6자리 코드) + 미국 주식(티커) 모두 지원.**

| 사용법 | 설명 |
|---|---|
| `/buy {종목코드} {수량}` | 시장가 매수 (미국은 현재가 조회 후 지정가로 제출) |
| `/buy {종목코드} {수량} {지정가}` | 지정가 매수 |
| `/buy {종목코드} max {금액}` | 금액 범위 내 최대 수량 매수 (국내: 원화, 미국: USD) |

**예시**
```
/buy 005930 10                 (삼성전자 10주 시장가)
/buy 005930 5 70000             (삼성전자 5주, 70,000원 지정가)
/buy 005930 max 1000000         (100만원 이내 최대 수량)
/buy IONQ 10                    (아이온큐 10주 시장가)
```

**동작 방식**: `src/commands/buy_command.py`. 종목코드가 6자리 숫자면 국내, 아니면
`mst/api/openapi_field_foren-us.mst`(로컬)에서 티커를 찾아 해외로 분기(API 호출
없음). 실제 주문 전 `_check_guards()`가 블랙리스트(`SettingsManager.get_blacklist()`,
`config/data/settings.json`)와 쿨다운(`cooldown_log.is_in_cooldown()`,
`config/data/cooldown_log.json` 계열)을 **API 호출 없이 로컬 파일로 먼저 검사**해
차단되면 즉시 반환한다. 이후 모드별 API 조합이 다르다:
- 국내 시장가/지정가: `ssam1802`(매수주문) 1건만 호출.
- 국내 `max`(금액 기반): ① `ivu10140`(현재가 조회)으로 가격을 얻어 수량 계산 → ②
  `ssam1802`로 시장가 주문. 2개 API를 순서대로 조합.
- 해외 시장가(가격 생략): ① `get_overseas_current_price()`(내부적으로 해외 기본시세
  API 호출)로 현재가 조회 → ② `skam2101`을 **지정가**(`frgn_ordr_typ_cd="2"`)로
  제출 — KB 해외 주문 API의 시장가 필드 처리가 명세에 없어 "현재가로 지정가 제출"로
  시장가를 흉내낸다. 지정가 입력 시엔 ①을 건너뛰고 `skam2101`만 호출.
- 해외 `max`: 위 해외 시장가와 동일하게 현재가 조회 → 수량 계산 → `skam2101` 지정가
  제출 (2개 API 조합).

**실행 검증**: 실거래 주문 API이므로 실제 실행은 생략하고 코드 리뷰로 대체(위 내용).

### `/sell`
종목을 매도합니다. **국내(6자리 코드) + 미국 주식(티커) 모두 지원.** 미국 주식은
보유수량 자동조회가 되지 않아 수량을 반드시 명시해야 합니다(전량 매도는 국내 전용).

| 사용법 | 설명 |
|---|---|
| `/sell all` | 보유 전체 종목 시장가 매도 (국내만) |
| `/sell {종목코드}` | 전량 매도 (국내만, 시장가) |
| `/sell {종목코드} {수량}` | 수량 지정 매도 (미국은 현재가 조회 후 지정가로 제출) |
| `/sell {종목코드} {수량} {지정가}` | 지정가 매도 |

**예시**
```
/sell all
/sell 005930
/sell 005930 5
/sell IONQ 3
```

**동작 방식**: `src/commands/sell_command.py`. 블랙리스트 검사(로컬)는 매도에도
동일하게 적용되지만(쿨다운은 매수 진입 제한용이라 매도엔 적용 안 함), 매도 성공 시
`cooldown_log.record_sell()`으로 로컬 로그에 매도 시각을 기록해 이후 `/buy`의 쿨다운
판정 근거로 쓴다(API 아님, 파일 기록). 조합 방식:
- 국내 수량+가격 지정: `ssam1801`(매도주문) 1건.
- 국내 수량만 지정(가격 생략) 또는 코드만 입력(전량): ① `ssqm1801`(보유주식 조회)로
  보유수량 확인 → ② `ssam1801`로 시장가 주문(전량인 경우 ①에서 얻은 수량 그대로).
- `/sell all`: `ssqm1801` 1회 조회 후 보유 종목 각각에 대해 블랙리스트 제외하고
  `ssam1801`을 종목 수만큼 반복 호출(N+1개 API 호출).
- 해외: 가격 생략 시 ① 현재가 조회(`get_overseas_current_price`) → ② `skam2101`
  지정가 제출(매수와 동일한 "지정가로 시장가 흉내" 방식). 보유수량 조회 API가 KB에
  없어 수량은 항상 사용자가 직접 입력해야 한다(전량 매도 미지원).

**실행 검증**: 실거래 주문 API이므로 실제 실행은 생략하고 코드 리뷰로 대체(위 내용).

### `/ccl`
미체결 주문을 전체 취소합니다.

```
/ccl pend
```

**동작 방식**: `src/commands/ccl_command.py`. ① `ssqm2341`(체결/미체결 조회,
`ccls_clsf="2"`로 미체결만)로 오늘자 미체결 주문 목록을 가져온 뒤, ② 각 주문마다

## 4. 설정 (브로커 무관 공용 값)

이 섹션의 명령은 전부 KB API를 호출하지 않고 `src/utils/settings_manager.py`의
`SettingsManager`(정적 메서드만 제공)를 통해 `config/data/settings.json`(경로 상수는
`src/paths.py`의 `SETTINGS_JSON`) 파일 하나를 읽고 쓴다. 조회는 `load_settings()`로
JSON 전체를 읽어 해당 키만 꺼내고, 설정은 값을 검증한 뒤 같은 JSON을 통째로 다시
저장(`save_settings()`)한다 — 여러 클라이언트/사용자가 같은 파일을 공유하므로
CLAUDE.md에 문서화된 대로 **서버 공용 설정**이다.

호출됨 — 예약이라고 안전한 것은 아니다). `daily`(평일 매일)와 `once`(1회, 실행 후
자동 삭제)는 반복 여부만 다를 뿐 저장/실행 경로는 동일하다.

**실행 검증 (2026-07-20)**: ✅ `once`로 예약 추가→목록 조회→삭제→목록 조회 순으로

## 6. API 직접호출 (`docs/api/md` 명세 기반)

명세 문서(`docs/api/md/*.md`)에 등록된 KB API라면 코드나 이름만 알면 바로 실행할 수
있는 범용 명령. 조회 API뿐 아니라 주문 API도 실행 가능하므로 실거래 계좌에서 특히
주의해서 사용하세요.

### `/api`
| 사용법 | 설명 |
|---|---|
| `/api {API코드}` | 해당 API 실행. INPUT 표에서 **선택지가 있는 필드**(필수여부 무관)는 번호 선택(대화형), 그 외는 타입(길이)만큼 공백으로 자동 채움 |
| `/api info {API코드}` | 실행하지 않고 어떤 필드가 선택 대상/공백 채움인지 미리보기 |
| `/api list [키워드]` | 코드/API명/업무구분으로 검색 (키워드 생략 시 전체) |

**예시**
```
/api SSQM1801           (보유주식 조회 실행)
/api info SSAM1802      (매수주문의 파라미터 미리보기)
/api list 계좌잔고
```

**동작 방식**: `src/commands/api_command.py` → `src/utils/api_spec.py`. `/api {코드}`는
`docs/api/api-list.json`(코드→md 파일 매핑)으로 명세 md 경로를 찾아 그 파일의 INPUT
표를 런타임 파싱한다(`registry.py`/`src/api/*.py` 자동생성 코드와 무관한 독립 경로).
파싱 후 **설명에 "코드:라벨" 선택지가 2개 이상 있는 필드만**(필수여부 무관) 사용자에게
번호로 고르게 하는 대화형 세션(`session_mgr.create_api_call_session`)을 열고, 나머지
필드(선택지 없음)는 전부 타입(길이)만큼 공백으로 자동 채운다 — 즉 종목코드·수량 같은
비선택형 값은 입력받지 않으므로 주문 API를 `/api`로 실제 체결시키기는 어렵다(9절의
전용 커맨드와의 핵심 차이). **KB 명세의 필수여부(Y/N)는 부정확해 무시하며, 요청 전
"필수 파라미터 누락" 검증도 하지 않는다**(실제 필수 여부는 KB 서버 응답으로 판단).
`info`/`list`는 실행 없이 명세만 읽는 읽기 전용 서브명령이다.

**실행 검증 (2026-07-20)**: ✅ `/api info IVU10280`(파라미터 미리보기), `/api list
거래량`(검색 2건), `/api IVU10280`(실제 호출) 모두 정상. 실거래 계좌에서 조회 API
실행까지 확인.

### `/call`, `/info`, `/list` — 저수준 직접 호출 (터미널/웹 전용)
`/api`보다 한 단계 낮은 저수준 통로. 지정한 필드만 JSON으로 채우고 나머지 INPUT
필드는 전부 타입(길이)만큼 공백으로 자동 채워 요청을 구성합니다.

| 사용법 | 설명 |
|---|---|
| `/call {API코드} ['{JSON}']` | API 호출 |
| `/info {API코드}` | 파라미터(타입/길이/선택지) 조회 (필수여부는 부정확해 표시 안 함) |
| `/list [키워드]` | 등록 API 코드/이름/업무구분 검색 |

**예시**
```
/call SZQM0771 {}
/call SSAM1801 {"is_cd":"005930","ordr_q":"1","ordr_uprc":"320000"}
/info SSAM1801
```

**동작 방식**: `/api`와 같은 `api_spec.py`를 쓰지만 대화형 세션을 만들지 않는다.
`/call`은 `full_blank_body()`로 **모든** INPUT 필드를 공백으로 채운 뒤, 사용자가
JSON으로 지정한 필드만 그 값으로 덮어써 곧바로 `execute_api_call()`을 호출한다 —
선택지 유무와 무관하게 전 필드를 직접 제어할 수 있어 주문 API도 실제로 체결시킬
수 있는 저수준 통로다(그래서 터미널/웹 전용, 텔레그램 봇에는 없음). `/info`는
`describe_spec()`, `/list`는 `search_api_entries()`로 명세만 조회한다. 이 세 명령은
`commands` 딕셔너리가 아니라 각 클라이언트 `_dispatch_direct()`의 하드코딩 분기로
처리된다(9절 전용 커맨드와 동일한 우회 패턴).

**실행 검증 (2026-07-20)**: ✅ `/info SSQM1801`, `/list 예수금`(조회 전용),
`/call SSQM0004 {}`(예수금내역 실제 호출 — 주문가능금액/예수금 정상 응답) 확인.
주문 계열 `/call`은 실거래 위험으로 실행하지 않고 조회 API로만 검증.

## 7. 자동매매 (폴링 기반, 09:00~15:30)

KB API에는 실시간 웹소켓이 없어 모두 REST 폴링(`src/utils/monitor_base.py`의
`MonitorBase` 상속)으로 동작합니다. 조건검색식 실시간거래(jggs)·VI감시(vi)·
테마(theme)·공매도(short/loan)는 KB API에 대응 API가 없어 지원하지 않습니다.

**공통 동작 방식**: 모든 감시 전략은 `MonitorBase`를 상속하며, `/start`로 시작하면
`threading.Thread(daemon=True)`가 각 전략의 `POLL_INTERVAL`초마다 깨어난다. 매 폴링마다
`_is_market_hours()`로 **평일 09:00~15:30 여부를 먼저 확인**하고(주말/장외 시간이면
아무것도 하지 않음), 장중이면 각 전략의 `_check_all()`이 KB 시세/차트 API를 폴링해
조건 충족 종목을 찾는다. 조건이 충족되면 저장해둔 명령 문자열(예: `buy 005930 1`)을
클라이언트의 `_execute_monitor_command()` → `_dispatch_direct()`로 넘겨 **실제 주문
API를 호출**한다 — 즉 `/start` 이후에는 사람이 개입하지 않아도 자동으로 실거래
주문이 나갈 수 있다. 감시 목록/설정값은 대부분 `config/data/settings.json`(서버 공용)에
저장되어 프로세스를 재시작해도 유지된다(단 "감시 실행 중" 상태 자체는 메모리에만
있어 재시작 시 다시 `/start` 필요).

> ⚠️ 아래 `add`/`list`/`remove`/설정 명령은 전부 파일에 값을 저장할 뿐 실제 매매를
> 하지 않지만, `/start`는 실거래 폴링을 시작해 조건 충족 시 자동으로 진짜 주문을
> 실행합니다. 이 문서의 실행 검증은 안전을 위해 `add`/`list`/`remove`/설정까지만
> 실제 실행하고 `/start`는 코드 리뷰로 대체했습니다.

**실행 검증**: `/start`는 실거래 폴링을 실제로 시작시켜(조건 충족 시 자동 주문) 실거래
위험이 있어 실행하지 않고 코드 리뷰로 대체. 시작/중단 판정·스레드 수명 관리 로직은
`MonitorBase`에서 확인.

## 9. API 전체 자동 실행 커맨드 (74개, 자동생성)

`docs/api/md` 하위 74개 API(국내 47 + 해외 27, OAuth 2개 제외) 전부를 이름만 알면
번호 선택 없이 즉시 실행할 수 있는 전용 슬래시 커맨드. `6. API 직접호출`의 `/api
{코드}`가 선택지 있는 필수 필드만 대화형으로 고르게 하는 것과 달리, 이 커맨드는
**필요한 파라미터를 한 줄에 순서대로 입력**해 바로 실행한다.

> ⚠️ **매수/매도 등 주문 계열 API도 이 경로로 실제 값을 넣으면 그대로 실거래가
> 실행됩니다.** `/api`는 선택지 없는 필드(종목코드·수량 등)를 공백으로 자동 채워
> 사실상 주문이 불가능하지만, 이 커맨드는 그런 필드도 위치 파라미터로 직접 받으므로
> 실제로 주문이 나갑니다. 사용 전 항상 어떤 값이 어떤 필드에 들어가는지 확인하세요
> (아래 "이름 찾는 법" 참고).

### 커맨드 이름 규칙

`{API코드}-{API명}`에서 공백을 밑줄(`_`)로 바꾼 한 단어 토큰입니다(대소문자
구분 없음). 예: `docs/api/md/국내주식/시세분석/IVU10280-거래량 상위-....md` →
`/IVU10280-거래량_상위`. 파일명 끝의 타임스탬프(`-YYYYMMDD-HHMMSS`)는 표시용일
뿐 토큰에 포함되지 않습니다.

### 파라미터 입력 규칙

INPUT 표의 **모든 입력 필드**에 값을 넣을 수 있으며, **두 가지 형식을 모두** 지원합니다.

- **① 값만 순서대로 (위치 방식)**: INPUT 표 순서대로 값만 공백으로 띄워 나열.
  ```
  /IVU10280-거래량_상위 0 1     → 거래소구분=0(통합), 시장구분=1(전체)
  /IVM10050-기업개요 000660     → 종목코드=000660 (SK하이닉스 기업개요)
  ```
- **② 항목명 지정 (JSON 방식)**: `{"항목한글명":"값"}` 토큰으로 지정. **웹 트리를
  클릭하면 이 형식으로 채워지므로, 빈 값만 실제 값으로 바꾸면 그대로 실행됩니다.**
  ```
  /IVM10050-기업개요 {"종목코드":"000660"}
  /IVU10280-거래량_상위 {"거래소구분":"0"} {"시장구분":"1"}
  ```

두 형식 모두 **넘기지 않은 필드는 자동으로 공백 채움**되므로 필요한 값만 주면 됩니다.
(KB 명세는 조회 API의 핵심 파라미터 — 종목코드 등 — 도 필수여부를 `N`으로 표기하는
경우가 많아, 필수/선택을 가리지 않고 모든 필드에 값을 넣을 수 있습니다. 위치 방식에서
필드 수보다 많은 값을 넘기거나 JSON 항목명이 틀리면 실행 대신 사용법을 안내합니다.)

`IVM10050-기업개요`의 `종목코드`(is_cd)는 KB 명세상 필수여부가 `N`이지만 실제로는
값을 줘야 의미 있는 조회가 되므로, 이 커맨드로 `000660`처럼 종목코드를 넘겨 바로
실행할 수 있습니다.

### 커맨드 이름 찾는 법

- `/api list [키워드]`로 코드/API명/업무구분 검색 후 `/api info {코드}` 로 INPUT
  필드와 선택지를 확인.
- 웹 클라이언트: `/api.html`(API 명세) 페이지의 좌측 트리, 또는 홈(`/`) 화면
  "사용 방법" 패널 하단 "전체 API 명령어(자동생성, 74개)"를 펼쳐 업무구분별로
  탐색. 항목을 클릭하면 "명령 실행" 입력창에 `/{토큰} {"필드한글명":"설명"} ...`
  형태(위 ② JSON 방식)로 자동 채워진다 — `"설명"`(또는 빈 값) 부분을 **실제
  값으로 바꾼 뒤** 실행하면 된다(예: `{"종목코드":""}` → `{"종목코드":"000660"}`).

### 동작 방식

`src/utils/direct_api_command.py`가 핵심 로직이며, `/api`와 동일하게
`docs/api/api-list.json`(코드→md 파일 매핑) + `docs/api/md/*.md`(INPUT 표 파싱)만
읽어 실행한다(`registry.py`/`CODE_TO_MODULE` 무관). 3개 클라이언트
(`src/run/main.py`/`src/run/terminal.py`/`src/web/client.py`)의 `_dispatch_direct()`
가 "알 수 없는 명령어" 처리 직전에 토큰을 판별해 공통으로 호출하므로, `commands`
딕셔너리에 74개를 개별 등록하지 않는다(`/call`·`/info`·`/list`와 같은 전례).
같은 이유로 `docs/command_guide_for_ai.md`에는 의도적으로 등록하지 않았다 — AI
자연어 변환이 이 커맨드를 스스로 생성해 실거래 주문을 잘못 실행하는 것을 막기
위함이다.
