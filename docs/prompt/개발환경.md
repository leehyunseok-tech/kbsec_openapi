# 개발 환경

## Python 버전 관리 / 가상환경

- 패키지 관리자로 **uv**를 사용한다. (프로젝트 전용 가상환경 격리, 빠른 설치 속도, `pyproject.toml` 기반 의존성/lock 관리)
- 설치 방법(Windows): `winget install --id=astral-sh.uv -e`
- 프로젝트 루트에서 `uv init`으로 초기화함. 아래 파일들이 생성됨.
  - `pyproject.toml` — 프로젝트 메타데이터 및 의존성 목록
  - `.python-version` — 프로젝트가 사용할 Python 버전 고정 (현재 `3.14`)
  - `main.py` — 진입점 예시 파일
  - `.venv/` — 이 프로젝트 전용 가상환경 (git에는 커밋하지 않음, `.gitignore`에 포함됨)
- `uv init`은 git 저장소가 없으면 자동으로 `git init`도 수행한다.

## 패키지 설치/관리

- 패키지 추가: `uv add <패키지명>` (예: `uv add openpyxl`)
- 패키지 제거: `uv remove <패키지명>`
- 의존성 동기화(가상환경에 lock 파일 기준으로 설치): `uv sync`

## 스크립트/코드 실행

- `uv run <파일.py>` 또는 `uv run python -c "..."`처럼 `uv run`을 사용하면 별도로 가상환경을 activate하지 않아도 프로젝트 전용 `.venv`에서 실행된다.

## 현재까지 추가된 의존성

- `openpyxl` — `docs/api/convert_xlsx_to_md.py`(API 명세 변환)와 `src/manage/generate_mst.py`(종목마스터 파이프라인 — 공식 명세 xlsx 읽기/선별표 xlsx 쓰기)가 사용.

- `fastapi`, `uvicorn[standard]` — 웹 인터페이스(`src/web/app.py`) 백엔드와 ASGI 서버. `uv add fastapi "uvicorn[standard]"`로 추가함.

## API 명세 목록 생성

- `docs/api/md` 하위의 개별 API 명세(.md) 파일들을 스캔해 전체 목록을 생성하는 스크립트: `docs/api/generate_api_list.py`
  - (참고: `docs/api/명세`, `docs/api/명세_md` 폴더는 각각 `docs/api/xlsx`, `docs/api/md`로 이름이 변경됨 — 한글/공백 경로가 일부 도구에서 인식되지 않는 문제 때문으로 보임)
- 실행: `uv run python docs/api/generate_api_list.py`
- 생성 결과:
  - `docs/api/api-list.md` — AI가 읽기 쉬운 표 형태의 전체 API 목록
  - `docs/api/api-list.json` — 프로그램에서 사용하기 쉬운 JSON 배열
- 동일 API 코드가 여러 파일로 중복 존재하는 경우(재수집 등) 파일명 타임스탬프가 가장 최신인 것만 대표로 남기고 나머지는 제외한다.
- `docs/api/md` 파일이 추가/변경되면 스크립트를 다시 실행해 목록을 갱신한다.

## API 클라이언트 코드 생성

- KB증권 REST API를 실제로 호출하는 파이썬 코드는 `docs/api/generate_api_client.py`가 `docs/api/md/*.md`의 "## INPUT" 표까지 파싱해 자동 생성한다.
- 실행: `uv run python docs/api/generate_api_client.py`
- 생성 결과 (수동 수정 금지, 재실행 시 덮어써짐):
  - `src/api/price_info.py`, `src/api/rank_info.py`, `src/api/chart.py`, `src/api/stock_info.py`, `src/api/market_info.py`, `src/api/investor_chart.py`, `src/api/order.py`, `src/api/reserve_order.py`, `src/api/account.py`, `src/api/withdraw.py` — 카테고리별 모듈, 함수 1개 = API 1개 (예: `src.api.order.ssam1801(...)`), 코드 배정 규칙은 스크립트의 `CODE_TO_MODULE` 딕셔너리 참고.
  - `src/api/registry.py` — API 코드 → 함수 매핑 (`REGISTRY`), `terminal.py`의 `call <코드>` 명령이 여기서 함수를 찾는다.
- 수기 작성 파일(생성 대상 아님): `src/api/client.py`(공용 요청 봉투/호출 로직), `src/api/auth.py`(토큰 발급).
- 인증: `config/config.py`에 실제 KB 개발자포털 발급 `real_client_key`/`real_client_secret`을 채운 뒤 `uv run python -m src.run.terminal`에서 `login real` → `call <코드> '<json>'`으로 테스트. **KB증권 개발환경(모의투자)은 아직 제공되지 않아 운영환경(`real`)만 사용 가능** — `dev_client_key`/`dev_client_secret`/`login dev` 코드 경로는 남아있지만 현재는 정상 동작하지 않는다.

## 종목마스터 파이프라인 (mst)

- KB 배포 원본 `.mst`(코스피 `mtsjname.mst` / 코스닥 `mtsoutjname.mst` / 미국 `FORENMST_US.MST`, UTF-8)를 `mst/origin/`에 갈아 놓고 아래 한 번만 실행하면 관련 문서와 런타임 데이터가 전부 재생성된다.
- 실행: `uv run python -m src.manage.generate_mst`
- 생성 결과 (수동 수정 금지, 재실행 시 덮어써짐):
  - `docs/mst/xlsx/openapi_mst_*.xlsx` — 공식 필드 명세(`docs/mst/xlsx/mst_*.xlsx`)에서 실제 사용/참조 필드만 선별한 표
  - `docs/mst/md/openapi_mst_*.md` — 선별표의 마크다운 판 + 코드→라벨 변환 규칙
  - `mst/api/openapi_field_kospi-kosdaq.mst` / `openapi_field_foren-us.mst` — `src/utils/stock_master.py`가 읽는 런타임 데이터 (중간 파일 없이 원본에서 직접 생성)
- 필드 인덱스/코드표의 근거는 공식 명세 `docs/mst/xlsx/mst_*.xlsx`이고, 어떤 필드를 사용/참조용으로 실을지는 스크립트 안 `CURATION` 표가 단일 소스다. 용도 문구에 적힌 API 코드는 `docs/api/api-list.md`에 실존하는지 실행 시 자동 검증된다.
- 과거 2단계 구조(`mst/create_openapi_mst.py` → `mst/api/generate_field_reference_mst.py`, 중간 산출물 `openapi_mtsjname.mst` 등 3종)는 타 증권사 레이아웃을 가정한 필드 라벨 오류(소수점매매상태→'주문유형', 현금증거금율구분→'매매수량단위코드' 등 의미가 정반대인 해석 포함)가 있어 폐지하고 이 파이프라인으로 교체·교정했다.

## 텔레그램 봇 / AI 자연어 / 자동매매

- 텔레그램 봇·AI 자연어 변환·자동매매 전략을 제공한다. 전체 기능 목록은 `docs/features.md` 참고.
- `src/run/main.py` — `TelegramBot`, 텔레그램 폴링 기반 운영 클라이언트. `src/run/terminal.py` — `TerminalClient`, 동일한 `src/commands/*.py` 핸들러를 공유하는 터미널 클라이언트(듀얼 클라이언트 아키텍처).
- KB API에는 실시간 웹소켓이 없어, 실시간 시세가 필요한 기능(트레일링 스탑/자동손절)도 `src/utils/monitor_base.py`(`MonitorBase`) 기반 REST 폴링으로 구현했다. 평가손익은 `SSQM2952`(잔고현황 조회)의 `val_yld` 필드를 그대로 사용.
- AI 자연어 변환(`src/utils/ai_command_converter.py`)은 `docs/command_guide.md`를 시스템 프롬프트에 그대로 삽입한다 — **명령어 추가/변경 시 반드시 `docs/command_guide.md`도 함께 갱신**해야 한다(`CLAUDE.md` 필수 규칙).
- 조건검색식 실시간거래(jggs/cond)·VI감시·테마분석·공매도분석은 KB API 74개 중 대응 API가 없어 미지원.
- `config/config.py`에 `telegram_token`/`telegram_chat_id`(봇용), `claude_api_key`/`claude_model`(자연어 변환용, 선택) 추가됨.

## 웹 인터페이스 (FastAPI + 순수 HTML/JS)

- 세 번째 클라이언트로 웹 브라우저 인터페이스를 추가함 (트리플 클라이언트: 텔레그램 `main.py` / 터미널 `terminal.py` / 웹 `src/web/`).
- 기술 스택: 백엔드는 **FastAPI + uvicorn**(순수 JSON API, `src/web/app.py`), 프론트엔드는 **서버 템플릿(Jinja2 등) 없이 순수 HTML+CSS+JS(fetch)** (`src/web/static/`) — 외부 JS 라이브러리/CDN 의존 없음.
- 실행: `uv run python -m src.run.web` 또는 `run-web.bat`/`run-web.sh` → http://localhost:8000 접속. 호스트/포트는 `KBSEC_WEB_HOST`(기본 `127.0.0.1`)/`KBSEC_WEB_PORT`(기본 `8000`) 환경변수로 변경.
- **다중 사용자 구조**: 브라우저 쿠키(`kbsec_web_sid`) 하나당 `WebClient` 인스턴스 하나(`src/web/session_store.py` 인메모리 매핑). 터미널/텔레그램과 달리 config.py의 앱키로 자동 로그인하지 않고, 각 사용자가 설정 화면에서 자기 client_key/client_secret(필수), Claude/텔레그램 키(선택)를 입력한다. 입력값은 서버 메모리에만 보관되고 파일로 저장하지 않으며, 서버 재시작 시 재입력 필요.
- 이 작업을 위해 기존 코드에 다중 인스턴스 대응 개선을 함께 적용함:
  - `handle_brk`/`handle_wave`/`handle_grid`에 `monitor=None` 인자 추가 — 전역 싱글턴(`set_*_monitor`)만 쓰면 웹에서 마지막 접속 사용자의 모니터가 전체를 가로채는 문제가 있어, 웹은 자기 모니터를 명시적으로 넘긴다(main/terminal은 기존 전역 방식 그대로).
  - `convert_natural_to_commands`/`send_photo`/`send_document`에 키·토큰 override 인자 추가(생략 시 config.py 전역값 — 기존 동작 불변).
- **알려진 제약**: 설정값·자동매매 감시목록(`config/data/settings.json`)은 `SettingsManager`가 파일 하나에 저장하므로 웹 사용자 전원이 공유한다(화면·README에 안내됨).

## 설치 스크립트 (install-project.bat / install-project.sh)

- GitHub에서 신규 클론한 환경을 원샷으로 세팅하는 스크립트. Python만 사전 설치되어 있으면 나머지는 자동:
  1. Python 존재 확인 — 없으면 https://www.python.org/downloads/ 링크를 안내하고 종료 (Windows는 Microsoft Store 별칭 stub도 미설치로 판정됨).
  2. uv 확인/자동 설치 — Windows: winget 우선, 실패 시 공식 PowerShell 인스톨러 폴백 + 현재 세션 PATH에 설치 경로(`%USERPROFILE%\.local\bin`, WinGet Links) 추가. macOS/Linux: curl(또는 wget)로 공식 인스톨러 + `$HOME/.local/bin` PATH 추가.
  3. `uv sync` — `.venv` 생성 및 uv.lock 기준 의존성 전체 설치. `.python-version`(3.14) 고정 버전이 시스템에 없으면 uv가 자동 다운로드.
  4. `config/config.py`가 없으면 `config.example.py`를 복사해 생성(있으면 건드리지 않음 — 멱등).
  5. (sh만) `run-*.sh`에 실행 권한 부여.
- 완료 후 `config/config.py`에 실제 키만 채우면 `run-*.bat`/`run-*.sh`가 바로 동작한다.
- 메시지 언어는 기존 스크립트 관례를 따름: `.bat`는 영문(cp949 콘솔 한글 깨짐 방지), `.sh`는 한글.

## 실행 스크립트 (bat/sh)

- 루트에 OS별로 분리된 실행 스크립트를 추가함. **`*.bat`는 Windows 전용, `*.sh`는 macOS/Linux 전용**이며 서로 대체 불가(둘 다 같은 OS에서 동작하는 게 아니라 각자 자기 OS에서만 씀).
  - `run-main.bat`(Windows) / `run-main.sh`(macOS·Linux) — 텔레그램 봇(`src/run/main.py`) 실행
  - `run-terminal.bat`(Windows) / `run-terminal.sh`(macOS·Linux) — 터미널 클라이언트(`src/run/terminal.py`) 실행
  - `run-web.bat`(Windows) / `run-web.sh`(macOS·Linux) — 웹 클라이언트(`src/run/web.py`, uvicorn) 실행
- 내부적으로 `uv run python -m src.run.main`/`uv run python -m src.run.terminal`을 호출하므로 가상환경을 미리 activate하지 않아도 된다. 스크립트는 자기 자신이 있는 디렉터리(프로젝트 루트)로 먼저 `cd`하므로 어느 위치에서 실행하든 동작한다. `-m` 모듈 실행 방식을 쓰는 이유는 아래 "소스 레이아웃(src/)" 참고.
- macOS/Linux에서는 최초 1회 `chmod +x run-main.sh run-terminal.sh`로 실행 권한을 부여해야 한다. Windows(`*.bat`)는 별도 권한 설정이 필요 없다.
- (참고) 최초 작성 시엔 `main.bat`/`client.bat`처럼 접두어 없는 이름이었으나, 두 스크립트가 무엇을 실행하는지 이름만으로 더 분명하도록 `run-` 접두어를 붙여 `run-main.*`/`run-client.*`로 리네임함. 이후 파일 자체(`cli_client.py`)도 `terminal.py`로 이름을 바꾸면서 스크립트도 `run-terminal.*`로 다시 리네임함. 이후 `main.py`/`terminal.py` 자체가 `src/run/`으로 옮겨가며 실행 방식도 `python <파일>` 직접 실행에서 `python -m src.run.<모듈>` 모듈 실행으로 바뀜.

## 소스 레이아웃 (src/)

- `src/` 폴더를 만들어 실행 코드를 한 군데로 모음: `utils/` → `src/utils/`, `api/` → `src/api/`, `telegram/` → `src/messenger/`(파이썬 표준 라이브러리에는 없지만 PyPI의 유명 `python-telegram-bot` 패키지와 이름이 겹치는 걸 피하려고 `messenger`로 개명), `main.py`/`terminal.py` → `src/run/`.
- `config/`, `docs/`, `logs/`는 이동하지 않고 프로젝트 루트에 그대로 둔다 — `config/config.py`는 gitignore 대상 실제 키 파일이라 소스 트리와 분리해두는 편이 안전하고, `docs/`는 코드가 아닌 문서/명세 자산이기 때문.
- 모든 임포트를 절대경로 `from src.utils...`/`from src.api...`/`from src.messenger...`/`from src.commands...` 형태로 통일함. `src/run/main.py`·`src/run/terminal.py`는 `uv run python -m src.run.main`처럼 **모듈(`-m`) 방식으로만 실행**한다 — 프로젝트 루트를 `sys.path`에 올려야 `src.*` 절대 임포트가 풀리기 때문에, `python src/run/main.py`처럼 파일 경로로 직접 실행하면 `ModuleNotFoundError: No module named 'src'`가 난다. `run-main.*`/`run-terminal.*` 스크립트가 이 호출 방식을 감싸고 있으니 일반적으로는 스크립트만 쓰면 된다.
- `src/`, `src/run/`에도 기존 `utils/`·`api/`·`telegram/`과 동일하게 `__init__.py`를 둔다(빈 패키지 마커).
- 파일 내부에서 `Path(__file__).resolve().parent...`로 프로젝트 루트(설정/로그/문서 경로)를 계산하던 곳은 모두 한 단계 더 깊어진 경로에 맞춰 `.parent`를 하나씩 추가함 — 예: `src/utils/*.py`는 `parent.parent`→`parent.parent.parent`.
- `docs/api/generate_api_client.py`(코드 생성 스크립트)의 출력 경로도 `PROJECT_ROOT / "api"` → `PROJECT_ROOT / "src" / "api"`로 갱신함. 이 스크립트는 `docs/api/`에 그대로 남아있음(이동 대상 아님).

### 후속 조정: `commands/`를 `messenger/`에서 분리 (멀티 메신저 대비)

처음엔 `telegram/commands/` → `src/messenger/commands/`로 옮겼으나, 사용자가
"앞으로 텔레그램뿐 아니라 다른 메신저도 붙일 예정"이라고 밝혀 구조를 한 번 더 조정함:

- `src/messenger/commands/` → `src/commands/` — 명령 핸들러(`handle_login`, `handle_buy` 등)는 텔레그램 전용이
  아니라 `main.py`/`terminal.py`가 공통으로 호출하는 메신저 무관 로직이라, `messenger/` 밑이 아니라 `src/` 바로
  아래(`api/`·`utils/`·`run/`과 나란히)로 옮기는 게 실제 역할에 맞음.
- `src/messenger/tel_send.py`/`tel_receive.py` → `src/messenger/telegram/tel_send.py`/`tel_receive.py` — 텔레그램
  Bot API 전송계층만 `telegram/` 하위 패키지로 한 단계 더 감싸둠. 나중에 디스코드/슬랙을 추가하면
  `src/messenger/discord/`, `src/messenger/slack/`처럼 나란히 추가하면 됨. 공통 인터페이스(추상 베이스 클래스 등)는
  아직 만들지 않음 — 실제 두 번째 메신저를 붙일 때 두 구현을 보고 공통점을 뽑는 게 더 정확해서 지금은 폴더
  구조만 미리 자리를 잡아둔 상태.
- 파일이 한 단계 얕아진 `src/commands/log_command.py`는 `Path(__file__)` 루트 계산도 `.parent`를 하나 줄임
  (`parent.parent.parent.parent` → `parent.parent.parent`, `src/utils/*.py`와 동일한 깊이).
